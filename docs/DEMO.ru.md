## Условия

Официальная Java Demo не требует покупки, но требует Microsoft-аккаунт. Пробный
одиночный мир ограничен примерно 100 минутами. Официально Java Demo предлагается
для Windows/macOS/Linux; iOS через сторонний Amethyst не является официально
поддерживаемой платформой. Общее разрешение на демонстрационную игру не является
подтверждением поддержки или одобрения этого порта Mojang.

Источники:
- https://www.minecraft.net/en-us/free-trial
- https://help.minecraft.net/hc/en-us/articles/4408948974989-Play-the-Minecraft-Java-Edition-Demo
- https://www.minecraft.net/en-us/eula

Amethyst уже реализует Microsoft-вход, распознаёт ответ NOT_FOUND для отсутствующего
Java-профиля, сохраняет demo-аккаунт и передаёт клиенту --demo. Новая кнопка использует
этот существующий механизм. Локальные профили не превращаются в Microsoft-аккаунты;
проверки доступа не отключены, сторонние копии клиента не используются.

## Установка и проверка

1. Сохраните резервную копию данных Amethyst через «Файлы». Не удаляйте установленное
   приложение до создания резервной копии. Скачайте IPA из успешного run этого PR.
2. Через AltStore Classic установите IPA с тем же Apple ID, что использовали ранее.
   Bundle ID сохранён; это обновление того же приложения, а не независимая копия.
   Бесплатную подпись нужно обновлять согласно ограничениям AltStore.
3. В аккаунтах выберите «Добавить аккаунт» → Microsoft (или пункт демоверсии).
   Войдите в настоящий Microsoft-аккаунт без Java Edition. При необходимости
   сначала создайте Xbox-профиль через официальный сайт Xbox.
4. После успешного входа выберите аккаунт, помеченный как демонстрационный.
   В боковом меню нажмите «Играть в демоверсию». Кнопка создаёт отдельный игровой
   профиль vanilla 1.21.4 в существующей папке .demo, с автоматическим выбором Java.
5. Дождитесь загрузок по официальным метаданным Mojang. Для 1.21.4 требуется Java 21;
   iOS runtime 21 включён в IPA и проверяется CI. Выбор подходящего runtime выполняет
   штатный JavaLauncher по метаданным игры.
6. Если появится ожидание JIT, включите JIT для приложения через поддерживаемый
   вашей версией iOS инструмент. При отсутствии подходящего инструмента отмените
   ожидание: пропуск проверки JIT не решает проблему запуска Java.
7. Критерий реального успеха: главное меню Minecraft → официальный Demo World →
   загруженный одиночный мир с сохранёнными ограничениями демоверсии.

## JIT

В исходниках используются stikjit://, UniversalJIT26.js и проверка isJITEnabled.
Это не доказательство работоспособности на iOS 27. Удалённый macOS runner не может
включить JIT на вашем телефоне. Установка через AltStore не включает его автоматически.
Ориентиры настройки Windows/pairing и текущая документация инструмента:
- https://faq.altstore.io/altstore-classic/enabling-jit
- https://github.com/StikDebug/StikDebug

Если инструмент требует Assign Script, используйте UniversalJIT26.js из Documents
Amethyst. Не публикуйте pairing-файл. Если iOS 27 не поддерживается выбранным
инструментом, этот этап остаётся заблокированным до появления совместимого метода.

### Если StikDebug ещё не установлен

1. Установите StikDebug через AltStore из официальных releases:
   https://github.com/StikDebug/StikDebug/releases
   README проекта сообщает, что в App Store его больше нет.
2. Установите loopback VPN, указанный разработчиками StikDebug (сейчас LocalDevVPN),
   и включите его. Проверьте текущий список требований в README StikDebug.
3. На Windows установите iloader из https://github.com/nab138/iloader/releases.
   Разблокируйте iPhone, подключите его по USB и подтвердите доверие компьютеру.
4. В iloader откройте Manage Pairing File. Напротив StikDebug нажмите Place и
   дождитесь сообщения об успешном размещении pairing-файла.
5. Откройте StikDebug на телефоне, нажмите Enable JIT и выберите Amethyst.
   При требовании Assign Script назначьте UniversalJIT26.js из Documents Amethyst.
6. Вернитесь в Amethyst и повторите запуск демоверсии. Если JIT не определяется,
   отмените ожидание и сохраните точный текст ошибки StikDebug для диагностики.

Источник этих шагов: https://github.com/StikDebug/StikDebug-Guide/blob/main/pairing_file.md
Проверять надо именно фактическое включение JIT на вашем iPhone, а не только наличие
установленного StikDebug. Обновление/сброс iOS может потребовать нового pairing-файла.

## Исправления и границы проверки

- Обработка строковых ошибок Microsoft/Xbox без вызова методов NSError у строки.
- Обработка неуспешного callback без зависания заблокированного списка.
- Правильный NSSet классов при чтении токенов из Keychain и освобождение CFData.
- Отсутствующие токены теперь требуют повторного входа, а не сообщают об успехе.
- Пропуск файлов аккаунтов без username; защита от пустого имени/ключа Keychain.
- Исправлен пустой NSAttributedString и небезопасный вызов sendActions у UIView.
- UI обновляется на главном потоке при обновлении токена на старте.
- Добавлена отмена ожидания JIT без запуска JVM при отмене.

Это исправления найденных дефектов, а не подтверждённое устранение всех вылетов.
Для оставшихся вылетов нужен журнал/ips с iPhone, без токенов и pairing-файлов.
CI проверяет сборку IPA и наличие runtimes. Скрипт check_demo_metadata.py проверяет
официальные метаданные 1.21.4, флаг демоверсии, SHA1 клиента и индекса assets.
Скачивание всех assets/библиотек самим приложением, Microsoft OAuth и запуск JVM
проверяются на устройстве. Minecraft-файлы не включаются в распространяемый IPA.

Если Microsoft отклоняет авторизацию стороннего OAuth-клиента, не подменяйте токены.
Пришлите точную ошибку; возможна необходимость регистрации разрешённого OAuth-приложения.
Законная альтернатива для проверки демо без JIT — официальный Minecraft Launcher
на Windows 11 с тем же Microsoft-аккаунтом. Мультиплеер и WellWorld не реализованы.
